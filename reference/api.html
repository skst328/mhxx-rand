1. 全体の作り: 状態はグローバル変数

クラスはなく、状態は全部モジュールのグローバル変数に持つ。関数は引数ではなく、グローバル変数を読み書きして動く。大きく 4 組ある。

組変数中身書き換える関数
乱数の状態x, y, z, w, txorshift128 の状態 (w がその位置の乱数)。t は計算の途中の値init ascend descend jump
f今の乱数位置 (初期値から何回進めたか)同上
r0〜r6直近 7 個の乱数 (r0 が古い)。お守り 1 個はこの 7 個から作るroll (jump も中で 7 回呼ぶ)
s乱数の初期値 [0x0194FD72, 0x79E6C985, 0x08DD9701, 0x41CFCE91] (書き換えない)—
お守りの表skill1, sp1第 1 スキルになれるスキル番号と、そのポイントの範囲 (最小, 最大)set_blue などの 4 つ
skill2, sp2第 2 スキルになれるスキル番号と、(マイナスの幅, 最大)同上
slotvalue充足値 1〜20 ごとの、スロット 1・2・3 になるしきい値 (乱数 % 100 と比べる)同上
th第 2 スキルが付くしきい値 (乱数 % 100 >= th なら付く)。風化 15・古びた 25・光る 35・なぞ 100同上
kind今の種類 (0 = 風化した、1 = 古びた、2 = 光る、3 = なぞの)同上
言語skillスキル番号 → スキル名 (日本語は 2 文字の略称)set_ja set_en set_zh
origin原産地の名前 (['マカ', '炭鉱'])。添字 0 がマカ錬金、1 がクエスト報酬同上
kinds, meldingお守りの種類の名前、錬金の名前 (['マカフシギ', '天運'])同上
kind_width, noskill, skill_width表示の幅と、第 2 スキルなしの表記同上
表示の設定num_of_charmsクエスト報酬で同時に鑑定する個数 (当たりフレームの計算に使う)。既定 40使う人が直接書く
showallrank錬金の当たりフレームを全ランク分出すか (False なら最高ランクだけ)同上
showrareレア度を表示するか同上
乱数位置の数え方。 jump(F) の後は r0〜r6 が位置 F〜F+6 の乱数で、f は F+7 になる。検索の関数が出す「found!frame is… f - 7」は、見つかったお守りの最初の乱数 (r0) の位置。

2. 呼ぶ順番

set_ja()                                   # 1. 言語 (skill と origin が決まる)
set_blue()                                 # 2. お守りの種類 (表が決まる)
p = parameter('連撃', 4, '痛撃', 5, 3, 'マカ')  # 3. 探すお守り (今の種類の表の中の位置に直す)
search(0, 10000, p)                        # 4. 探す (結果は print するだけ)

parameter は今の言語と種類の表を使って位置に直すので、1・2 より後に呼ぶ。種類を変えたら p も作り直す。

3. データの形 (p と c)

p: 探すお守り (parameter の戻り値)

添字名前中身
0_id1第 1 スキルの、skill1 の中での位置 (スキル番号ではない)。指定なしは -1
1_sp1第 1 スキルのポイント
2_id2第 2 スキルの、skill2 の中での位置。指定なし ('') は -1
3_sp2第 2 スキルのポイント
4_slotスロット数
5_origin原産地 (0 = マカ、1 = 炭鉱)
6, 7_len1, _len2skill1・skill2 の長さ (割る数)

第 1・第 2 スキルを両方 '' にすると、_id1 は 0 になる。

c: 作ったお守り (getcharm の戻り値)

添字中身
0第 1 スキルの番号
1第 1 スキルのポイント
2第 2 スキルの番号。付かなければ -1
3第 2 スキルのポイント (付かなければ 0)。第 1 スキルと同じスキルでも、マイナスでも、そのままの値
4スロット数 (0〜3)
5充足値 (第 2 スキルが第 1 と同じかマイナスなら、第 2 スキルのポイントを 0 として計算)
6スロットを決めた乱数 % 100
7レア度

4. 設定: お守りの種類と言語

関数何をする状態
set_blue()風化したお守りの表にする (th = 15、kind = 0)書く: skill1 sp1 skill2 sp2 slotvalue th kind
set_red()古びたお守り (th = 25、kind = 1)同上
set_yellow()光るお守り (th = 35、kind = 2)同上
set_white()なぞのお守り (th = 100 なので第 2 スキルは付かない、kind = 3)同上
set_ja()日本語にする (スキル名は 2 文字の略称。「毒　」のように全角スペースで埋めたものがある)書く: skill origin kinds melding kind_width noskill skill_width
set_en()英語にする同上
set_zh()簡体字の中国語にする同上

5. 乱数

関数何をする状態
init()状態を初期値 s に戻し、f = 0 にする書く: x y z w t f
ascend()乱数を 1 つ進める (xorshift128)。f += 1書く: x y z w t f
descend()乱数を 1 つ戻す (ascend の逆)。f -= 1書く: x y z w t f
roll()r0〜r6 を 1 つずらして今の w を r6 に入れ、ascend する書く: r0〜r6 (と ascend の分)
jump(frame)位置 frame へ一気に飛び、roll を 7 回する (後は r0 = 位置 frame の乱数、f = frame + 7)。GF(2) の多項式 xframe mod (特性多項式) を作り、それで状態を組み立てる書く: x y z w t f r0〜r6
jumpshort(frame)ascend か descend を 1 つずつ繰り返して frame へ行き、roll を 7 回する。近い位置用。今の f から数えるので、行き先は jump(frame) と同じになる書く: 同上
poly_mul(p1, p2)GF(2) の多項式の掛け算 (繰り上がりなし)—
poly_mod(p, m)GF(2) の多項式の剰余 (m = 0 は不可)—
poly_pow_mod(base, exp, mod)GF(2) の多項式のべき乗の剰余—
rand(num1, num2)錬金の個数や色を決める別の乱数。num1 の下位 16 bit から始め、「0 なら 1 にして ×176 mod 65363」を num2 回—

6. お守りを作る

関数何をする状態
getcharm(_origin)r0〜r6 からお守り c を作る。r0 第 1 スキル、r1 そのポイント、r2 第 2 スキルが付くか、r3 第 2 スキル。マカ (0) は r4 が第 2 のポイント、r5 がスロット。炭鉱 (1) は r4 が偶数ならマイナスもありで r5 がポイント、r6 がスロット。第 2 スキルが付かなければ、スロットは r3読む: r0〜r6 と表
slot(fill, num1)充足値 fill と乱数 % 100 からスロット数を決める読む: slotvalue
rare(slot, fill)スロット数 × 2 + 充足値から、種類ごとのレア度を決める読む: kind
parameter(str1, num1, str2, num2, num3, str3)探すお守り p を作る。スキル名 (今の言語の略称)・ポイント・スロット数・原産地の名前を渡す。'' はそのスキルを指定しない読む: skill origin skill1 skill2

7. お守りの検索 (素の Python)

どれも jump(start) してから roll を step 回繰り返し、毎回 getcharm で作ったお守りを比べる。結果は print するだけで、何も返さない。

関数何をする出力
search(start, step, p)p と同じお守りを探す。第 2 スキルが '' なら、第 2 スキルが画面に出ないもの (付かない・第 1 と同じ・0) だけprint 位置と時間
search_greater(start, step, p)スキルが同じで、ポイントとスロットが p 以上のものを探す。第 1 か第 2 を '' にすると、もう片方だけで探すprint msg (お守りと当たりフレーム)
search_fill_slot(start, step, _fill, _slot, str1)充足値とスロット数が同じものを探す (スキルは問わない)print 位置とお守り

8. お守りの検索 (numba)

7 と同じ検索を numba でコンパイルして速くしたもの。状態を tuple と numpy の配列で渡し、見つけた位置の一覧を返す。show_fast などが、見つけた位置へ jump し直して表示する。

関数何をする状態・出力
show_fast(start, step, funcname, p)funcname が 'search' か 'search_greater'。中で下の loop_*_nj を選んで回すprint 書く: 乱数の状態
show_fast_multi(start, step, *p_list)どれかの p 以上のお守りを探す (search_greater の複数版)。p はどれも第 2 スキルありで、原産地は最初の p のものprint 書く: 乱数の状態
get_env()今の種類の表を numpy の配列の tuple にする (je)読む: 表
loop_search_nj(num, jr, js, jp, je) njitsearch の中身見つけた位置の List
loop_search_greater_nj(…) njitsearch_greater の中身 (両方のスキルを指定)同上
loop_search_greater_skill1_nj(…) njit同 (第 1 スキルだけ指定)同上
loop_search_greater_skill2_nj(…) njit同 (第 2 スキルだけ指定)同上
loop_search_greater_multi_nj(num, jr, js, jp_list, je, _origin) njitshow_fast_multi の中身同上
ascend_nj(js) descend_nj(js) roll_nj(jr, js) njitascend・descend・roll を、状態の tuple を受け取って返す形にしたもの (js = (x, y, z, w, t, f)、jr = (r0, …, r6))新しい tuple
getcharm_nj(_origin, jr, je) slot_nj rare_nj njitgetcharm・slot・rare と同じ (表は je から読む)c の tuple など
mag_nj(m) div_nj(a, c, r) njit「a % m == r か」を割り算なしで手早く見る (掛け算で代用)。偽陽性があるので、通った後に a >= r を確かめて消す真偽

9. 錬金と当たりフレーム

錬金は、錬金した位置 F の 1 つ前の乱数で、出るお守りの種類と個数を決め、F から順にお守りを作る。お守り 1 個で乱数を 4 個 (第 2 スキルなし) か 6 個 (あり) 使う。マカフシギ錬金が juju、天運の錬金が halcyon。

関数何をする状態・出力
juju_colors(seed, rank)マカフシギ錬金で出る種類の並び。風化した (0) と古びた (1) が、rand(seed, 1)・rand(seed, 2) で決まる個数ずつ。ランク 4 は風化 2 個 + 古びた 1〜2 個種類の一覧
halcyon_colors(seed, rank)天運の錬金で出る種類の並び (光る・古びた・なぞの)。個数も種類も rand で決まる種類の一覧
meldingpush(frame, colorarrayfunc, rank)位置 frame で錬金したときに出るお守りを、順に作って表示する。種類ごとに set_* を切り替え、最後に元の種類に戻すprint 書く: 乱数の状態 (表は戻す)
jujupush(frame, rank=4)マカフシギ錬金の結果 (meldingpush)print
halcyonpush(frame, rank=4)天運の錬金の結果print
aimpoint_melding(num1, colorarrayfunc, rank)今のお守り (r0 から作るもの) に届く錬金の位置を、手前 num1 個について調べる (その位置で錬金すると、今の種類のお守りとしてここを通るか)print 乱数は戻す
_aimpoint_juju(rank) _aimpoint_halcyon(rank)手前 19 個 (マカフシギ) / 31 個 (天運) で aimpoint_meldingprint
aimpoint_juju() aimpoint_halcyon()上を全ランク分 (showallrank) か最高ランクだけprint
aimpoint_blue()風化したお守り用の簡易版。当たりフレームの数 (1〜3) だけ出すprint 乱数は戻す
aimpoint_quest(num1)クエスト報酬で num1 個同時に鑑定するときに、今のお守りに届く位置 (お守り 1 個で乱数を 4 個か 7 個使う)print 乱数は戻す
show_aimpoint(array, func)当たりフレームの数と、◯ / Ｘ の並び (右端の [ ] が今の位置) を表示するprint

11. 調合・クエスト報酬からの位置の特定

お守りではなく、調合でできた個数やクエスト報酬の並びから、乱数位置を逆に探す。乱数の列を、決まった間隔 (調合は 5 個おき、報酬は 1 個おき) で拾った値の並びとして、KMP で照合する。

関数何をする出力
search_combo(start, step, combo_str)調合したときの所持数の並び (空白区切り) から、調合を始めた位置を探す。先頭 3 つと最後の 99 は使わない。差が 2〜4 でないところがあれば、そこに印を付けて止まるprint
search_reward(start, step, bonus_th, target_str, reward_table)採取ツアーのクエスト報酬 (1 段目の 4〜8 個) から、報酬を作る直前の位置を探す。bonus_th は運気スキルによるしきい値print
search_stride_nj(step, js, A, stride, lut) njit乱数 (下位 16 bit % 100 を lut で記号に直したもの) の列を stride おきに見て、A に一致する位置を KMP で探す位置の List
kmp_prefix_nj(A) njitKMP の失敗関数配列
combo_lookuptable()% 100 から調合でできる個数へ: 0〜24 は 2 個、25〜74 は 3 個、75〜99 は 4 個配列
reward_lookuptable(reward_table)% 100 から報酬の何番目のアイテムかへ (reward_table の値が累積のしきい値)配列
check_bonus(len1, four_nums, bonus_th)報酬の個数が合うか (乱数の下位 5 bit が bonus_th 未満なら、報酬が 1 つ増える)真偽
show_invalid_differences(dif_A, combo_str)調合の差の並びで 2〜4 でないところを表示するprint 真偽

12. 移植するときの注意

  • 結果を返さない。 検索の関数は print するだけ。比べるデータを作るときは、print を横取りするか、loop_*_nj の戻り値 (位置の一覧) を使う。
  • p はスキル番号ではなく、表の中の位置。 種類 (set_*) ごとに表が違うので、同じスキルでも p が変わる。
  • 位置は f - 7。 jump の後の f は 7 進んでいる (r0 が位置 f - 7 の乱数)。
  • 錬金の関数は、種類の表を書き換えて戻す。 meldingpush と aimpoint_melding は、途中で set_* を呼んでから元の種類に戻す。途中で止まると、表が別の種類のままになる。
  • 第 2 スキルが画面に出ないことがある。 第 1 と同じスキルのときと、ポイントがマイナス (炭鉱) のとき、c[3] はそのままの値で、充足値の計算だけ 0 として扱う。
  • numba の範囲。 show_fast は、f + step が 263 未満になるように使う (numba の中で int64 を超えると float になる)。
